# A11Y-001 — AI Analytics Accessibility Pass

**Epic:** Accessibility
**Priority:** Medium
**Status:** Todo
**Dependencies:** —
**Related docs:** [../../docs/AI_ANALYTICS.md](../../docs/AI_ANALYTICS.md) · [../../docs/COMPONENT_LIBRARY.md](../../docs/COMPONENT_LIBRARY.md) · [../../docs/CODING_STANDARDS.md](../../docs/CODING_STANDARDS.md)

> Scope guard: this task covers **accessibility improvements only**. No new features, no UI redesign, no calculation or business-logic changes.

---

## 1. Goal

Make the AI Analytics module (`src/features/finance/aiAnalytics/`) usable with a screen reader and keyboard, without changing how it looks or what it computes. The module is chart-heavy (Recharts SVG) and, per the architecture review, only ~3 of 52 component files currently carry any `aria-`/`role` attributes — its scores, trends, forecasts, and behavior charts are effectively opaque to assistive technology today. This task closes that gap by adding semantic labels, roles, text alternatives, and reliable keyboard operation to the existing components as they are.

## 2. Scope

**In scope**

- All components under `src/features/finance/aiAnalytics/components/**` and the page `src/features/finance/aiAnalytics/pages/AiAnalytics.tsx`.
- Charts rendered via Recharts (radar, line/area trend, bar, heatmap, radial score, etc.) inside the module.
- Interactive controls inside the module (buttons, the AI Coach input, the What-If scenario controls, any toggles/expanders).
- New i18n keys for accessible labels / chart text alternatives (additive only), added to both `en` and `th` in `src/i18n/translations.ts`.

**Out of scope**

- Any file outside `src/features/finance/aiAnalytics/**` (except additive `translations.ts` keys used by this module).
- The AI engine under `.../aiAnalytics/engine/**` — no analyzer, scoring, forecast, recommendation, or executive-summary logic is touched.
- Shared UI primitives outside this module (e.g. `src/components/ui/**`) — do not refactor them here; if a primitive genuinely blocks a fix, flag it as a follow-up task rather than editing it in this pass.
- Visual redesign, layout changes, colour/contrast re-theming beyond what is strictly required to expose an already-invisible focus outline.

## 3. Functional Requirements

1. Every chart in the module exposes a programmatic name and a concise text summary of what it represents, so a non-visual user learns the same headline the chart conveys visually (e.g. "Financial health score: 72 out of 100").
2. Every interactive control has an accessible name describing its action in context (e.g. the coach send button, What-If sliders/inputs, section expanders).
3. All existing on-screen behaviour is preserved exactly: same rendered output, same click/tap results, same numbers.
4. All new user-facing strings (labels, summaries) are translatable and provided in both `en` and `th`, matching the module's existing `aiAnalytics.*` key style and the `translate({ key, params })` pattern already used in the module.

## 4. Non-Functional Requirements

1. **No behavioural regression** — existing unit/integration/e2e tests for the module continue to pass unchanged; no test is weakened to make a change pass.
2. **No calculation change** — analyzer/engine outputs are byte-for-byte identical before and after.
3. **Performance-neutral** — no added re-renders or heavy work on the render path; labels are derived from data already computed.
4. **Consistency** — follow the store → component conventions and the `schema(t)` / `translate` i18n patterns already documented in [CODING_STANDARDS.md](../../docs/CODING_STANDARDS.md); do not introduce a new accessibility pattern where the codebase already has one.
5. **Type-clean** — `npx tsc -b` and `npm run lint` stay green.

## 5. Technical Requirements

1. Prefer native semantics first: use real `<button>`/`<a>` (the module already does — keep it), headings for section titles, and lists for list-like content, before reaching for ARIA. ARIA supplements native semantics; it does not replace them.
2. For Recharts SVG, wrap each chart's container with an appropriate role and accessible name, and provide a text alternative that is available to screen readers even though the SVG paths are decorative. Recharts' own `accessibilityLayer` / `role`/`aria-label` props (where the installed version supports them) may be used, but a container-level label + visually-hidden summary is the baseline that must work regardless.
3. Introduce (or reuse, if one already exists in the module) a single small visually-hidden text mechanism (e.g. an `sr-only` utility class already present in Tailwind, or a tiny local helper) for chart summaries — do not hand-roll inline `position:absolute` hacks per chart.
4. All label/summary text comes from `translations.ts` keys, never hard-coded English or Thai literals in components.
5. Keyboard focus order must follow visual order; do not add `tabindex` values other than `0`/`-1`, and do not create focus traps.

## 6. Accessibility Requirements

- **`aria-label`** — add appropriate `aria-label` to interactive controls and chart containers that lack an accessible name (icon-only buttons, chart wrappers, the coach input if unlabeled).
- **`aria-labelledby`** — where a visible section heading already names a chart/region, associate the region with it via `aria-labelledby` (pointing at the heading's `id`) instead of duplicating text in an `aria-label`.
- **`role` for charts** — add `role="img"` (with a text alternative) to non-interactive chart figures, or `role="figure"`/`figure`+`figcaption` semantics where a caption is visible; use `role="group"`/`role="region"` for composite panels only where it adds real structure.
- **Screen reader support** — provide a concise, data-driven text summary for each chart (the key number/trend it shows), so the meaning is available without seeing the graphic.
- **Keyboard navigation** — ensure every control reachable by mouse/touch is reachable and operable by keyboard (Tab/Shift-Tab to reach, Enter/Space to activate), with a **visible focus indicator**; verify the AI Coach input, What-If controls, and any expanders/toggles.
- **Text alternatives for charts** — where a chart has no meaningful non-visual equivalent, add a short alt/summary describing what it depicts; where a data table would serve better, a visually-hidden summary of the headline figures is acceptable for this pass (a full accessible data-table alternative can be a follow-up).
- **Preserve existing UI and business logic** — no visual redesign, no layout change beyond exposing focus states.
- **Do not change calculations** — engine/analyzer output is untouched.
- **Do not redesign components** — modify markup/attributes for semantics only; component structure and styling stay as-is.

## 7. Acceptance Criteria

1. Every chart in `aiAnalytics/components/**` has both an accessible name and a screen-reader-available text summary of its headline figure/trend.
2. Every interactive control in the module has a non-empty accessible name that describes its action.
3. Keyboard-only walkthrough of the AI Analytics page reaches and operates every control in logical order, with a visible focus indicator on each.
4. No visual diff on the page in light or dark mode (aside from focus outlines that were previously missing).
5. Analyzer/engine outputs and all displayed numbers are identical to `main` before the change.
6. All new strings exist in both `en` and `th` blocks of `translations.ts`; no hard-coded literals remain in the touched components.
7. `npm run lint`, `npx tsc -b`, and `npm test` are green; existing AI Analytics tests pass without modification.

## 9. Test Plan

**Automated**

- Unit/RTL: for a representative sample of chart components and each interactive control type, assert the presence of an accessible name (`getByRole(...)` / `toHaveAccessibleName(...)`) and, for charts, the presence of the text summary. Use the module's existing Vitest + Testing Library setup (jsdom) — see [TESTING_GUIDE.md](../../docs/TESTING_GUIDE.md).
- Regression: run the full existing AI Analytics unit/integration suite unchanged to confirm no behavioural drift; confirm a snapshot/DOM check that displayed numbers are unchanged.
- Lint/type: `npm run lint`, `npx tsc -b`.

**Manual**

- Keyboard-only pass through the AI Analytics page: Tab to every control, activate with Enter/Space, confirm visible focus and logical order; confirm no focus trap in the coach input / What-If panel.
- Screen-reader spot-check (NVDA or VoiceOver, or Chrome + the accessibility tree in DevTools) on 3–4 representative charts and the coach input: confirm each announces a meaningful name + summary.
- Light and dark mode visual check to confirm no unintended visual change.
- (Optional, if available in CI) an axe/`@axe-core` scan of the page as an advisory signal — record results, but the acceptance gate is criteria 1–7, not a zero-violation axe score.
